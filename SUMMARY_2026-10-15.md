### B. Perbaikan Bug Notifikasi Tiket & Request

- **Identifikasi Masalah**:
  - Pada notifikasi lama, teks yang muncul adalah:  
    `The status of your ticket '' has been updated to '{"id":3,"name":"Progress","created_at":"2024-10-24T19:24:02.000000Z",...}'.`
  - **Penyebab 1**: Model `Request` menggunakan kolom `judul` (bukan `title`), sehingga properti `$this->request->title` bernilai kosong (`''`).
  - **Penyebab 2**: Relasi Eloquent `status` mengembalikan model `App\Models\Status`. Saat digabungkan langsung dalam kurung kurawal string (`"{$this->request->status}"`), PHP/Laravel otomatis mengonversinya menjadi representasi JSON mentah dari seluruh atribut tabel status.

- **Solusi pada `app/Notifications/RequestStatusChanged.php`**:
  - Menyesuaikan penanganan model secara fleksibel untuk `App\Models\Request` (`judul`) dan `App\Models\Ticket` (`title`).
  - Mengekstrak nama status secara aman (`$status->name` atau string status).
  - Mengubah pesan menjadi kalimat bahasa Indonesia yang komunikatif dan profesional:  
    *Contoh*: **`Status Request 'test it' telah diperbarui menjadi 'Progress'.`**
  - Menyertakan metadata pendukung: `is_ticket`, `url` tujuan (`/detailrequest/{id}` atau `/detailticket/{id}`), dan `updated_by`.

- **Perbaikan Data Database**:
  - Sebanyak **35 baris data notifikasi lama** pada tabel `notifications` yang rusak telah diperbaiki isi kolom `data`-nya sehingga riwayat pengguna langsung bersih tanpa teks JSON.

### C. Pengiriman Notifikasi Tepat Sasaran Per User

- **Penyaringan Pengirim (*Self-Action Filter*)**:
  - Pengguna tidak lagi menerima notifikasi atas perubahan status yang ia lakukan sendiri (`$creator->id !== Auth::id()`).

- **Pemicu Notifikasi Baru**:
  1. **Penugasan Tiket Baru**: Di `TicketController::storeticket`, jika pembuat tiket memilih advisor (`advisor_id`), sistem otomatis mengirim notifikasi penugasan ke user advisor tersebut.
  2. **Pengalihan Tiket (*Takeover*)**:
     - Saat request alih tiket dikirim (`TicketController::takeover`), notifikasi permohonan alih tiket dikirim ke user target.
     - Saat disetujui (`takeoverAccept`) atau ditolak (`takeoverReject`), notifikasi konfirmasi dikirim kembali ke user pemohon.
  3. **Persetujuan Request**: Di `RequestController::approveRequest` dan `rejectRequest`, notifikasi hasil *approval* otomatis dikirimkan ke pembuat request.

### D. Sistem Notifikasi Real-Time & Dropdown Responsif

- **Backend Controller (`app/Http/Controllers/NotificationController.php`)**:
  - `getUnread(Request $request)`: Mengembalikan data JSON notifikasi yang belum dibaca beserta hitungan *badge* untuk user yang sedang aktif.
  - `markAsRead(Request $request, $id = null)`: Menandai notifikasi tertentu atau seluruh notifikasi sebagai telah dibaca via AJAX.
  - `index()`: Menyajikan halaman riwayat lengkap seluruh notifikasi pengguna (`/notifications`) dengan pagination.

- **Routing (`routes/web.php`)**:
  - `GET /notifications` -> `NotificationController@index`
  - `GET /notifications/unread` -> `NotificationController@getUnread`
  - `GET /notifications/mark-as-read` -> `NotificationController@markAsRead`
  - `POST /notifications/mark-as-read/{id?}` -> `NotificationController@markAsRead`

- **Frontend & Navigasi Header (`resources/views/layouts/header.blade.php`)**:
  - **Responsivitas Dropdown**: Menggunakan state inline Alpine.js `x-data="{ notifOpen: false }"` murni yang 100% bebas dari risiko *race condition* atau *reference error*.
  - **Zero-Latency Render**: Notifikasi awal langsung dirender menggunakan Blade saat halaman dimuat, sehingga tidak ada jeda tunggu saat pertama kali icon lonceng diklik.
  - **Auto-Polling Real-Time**: Script background `pollNotifications()` mengecek pembaruan ke server setiap **8 detik**. Jika ada tiket/request baru dari tim lain, indikator titik merah (*pulsing red dot*) dan daftar dropdown akan otomatis terbarui tanpa refresh.
  - **Tandai Dibaca Instan**: Mengklik *Tandai Dibaca* langsung mereset tampilan dan badge ke nol di browser secara instan sambil mengirim update ke server di latar belakang.
  - **Navigasi Klik**: Mengklik item notifikasi otomatis menandainya sebagai terbaca dan mengarahkan pengguna ke workspace detail tiket/request terkait.

- **Halaman Riwayat Notifikasi (`resources/views/notifications/index.blade.php`)**:
  - Tautan *"Lihat Semua Riwayat"* di bagian bawah dropdown kini membuka halaman tersendiri dengan daftar notifikasi lengkap, filter badge baru, dan tombol *"Lihat Detail"*.
